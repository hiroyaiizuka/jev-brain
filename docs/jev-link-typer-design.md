# Jev でリンクに型を付ける（別プラグイン）：設計メモ

更新日: 2026-09-20。本人の 3 つの指摘（2026-09-20）を反映した設計の出発点。ExcaliBrain フォーク（本リポジトリ）の外に作る小さな別プラグインで、フォーク側は変更しない。仮の名前は jev-link-typer（本人が決める）。

## 1. 何をするか

エディタで `[[X]]` の上にカーソルを置いてホットキーを押すと、Jev がその場に合うオントロジーのフィールドを判定し、`[[X]]` を `(field:: [[X]])` に書き換える。ExcaliBrain の親・子・友・前後の分類がそのまま付く。

## 2. 本人の指摘と、それが設計に与えること

### ① 既存サジェスターは順番が逆

ExcaliBrain のサジェスター（`src/Suggesters/OntologySuggester.ts`）は `::` などのトリガーで**先にフィールド名**を選び、そのあとで `[[リンク]]` を書く。サジェストの時点ではリンク先が決まっていないので、Jev に渡す state に相手のノートを入れられない。

→ 「既存サジェスターに候補を足す」のではなく、**貼った後のリンクに型を付ける**新しい入口にする。入力は「今のノート」「リンク先ノート」「リンクの前後の文」が揃っている状態。ExcaliBrain 本体は触らず、その設定（`hierarchy`）を読むだけの別プラグインで作れる。

### ② 方向は Jev に聞かなくても引ける

フィールド → 方向（親・子・左友・右友・前・次）の対応は ExcaliBrain の設定に決定的に書いてある。

→ それでも**フィールドの Choice と方向の Choice を両方聞き**、食い違ったら「自信なし」として通常の並び順（設定の順）に戻す。Jev は同じ state に対して質問を独立・並列に評価するので、1 回の呼び出しで両方取れる。これを整合性チェックとして使うほうが堅い。

### ③ 「候補を出す」の意味を絞る

Jev はテキストを生成しないので、新しいオントロジー項目の発案はできない。できるのは**既存項目の順位付け**だけ。語彙を増やす作業は LLM 側（またはユーザー）に残る。

→ 候補の全体集合は常に ExcaliBrain の `hierarchy`（parents / children / leftFriends / rightFriends / previous / next の全フィールド）。Jev の Choice はこの集合に対する順位と確率。

## 3. 流れ

```text
ホットキー（カーソルが [[X]] の上）
  → 状態を作る: 今のノート（本文・frontmatter）、X のノート（本文・frontmatter、あれば）、
               リンクの前後 N 文字、ExcaliBrain の hierarchy（フィールド一覧と方向）
  → Jev を 1 回呼ぶ（2 つの質問を並列に）:
       Q1 Choice: このリンクに付けるフィールドは？（候補 = hierarchy の全フィールド）
       Q2 Choice: このリンクの方向は？（候補 = 親 / 子 / 左友 / 右友 / 前 / 次）
  → 整合性: Q1 の上位候補のフィールドが設定上持つ方向 と Q2 の答えが一致 → その順で提示
            不一致 → 「自信なし」。設定の並び順で提示し、確率は表示しない
  → 候補をサジェスト UI（Obsidian の SuggestModal）で見せ、Enter で確定
  → エディタの [[X]] を (field:: [[X]]) に置換（Dataview のインラインフィールド。行頭なら field:: [[X]] でもよい）
```

ExcaliBrain は `metadataCache` の変更を拾って次の描画で反映する（`Scene.setTimer()` の `indexUpdateInterval`）。

## 5. jev-brain（フォーク）との関係

- フォーク側はネットワークを使わない状態を保つ（3D はローカル完結）。Jev への通信は別プラグインに閉じる。
- 3D で使う「抽象度アップ／ダウン」のフィールド集合（`docs/3d-design.md` §3-1）は、この別プラグインが付けるフィールドと同じ語彙。両方が ExcaliBrain の `hierarchy` を正本にする。
