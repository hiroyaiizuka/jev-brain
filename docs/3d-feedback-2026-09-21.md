# 3D ビューのフィードバック（2026-09-21、本人）

3D-1 の実機（`artifacts/3d1-e2e/C-3d-8notes.png`）を見た本人のフィードバック。原文のまま。模式図は `docs/images/3d-feedback-mock-2026-09-21.png`。反映の設計は `docs/3d-design.md` §6、チケットは 3D-2（LEV-100）の子。

---

動くところまではOK。ただ、今の見た目だと「床の上にノートが浮いている」ように読めないので、投影方法と視覚の優先順位を変えてほしい。

## 1. 投影を「回転」から「斜投影（キャビネット図法）」に変える【最優先】

今は地面を yaw 回転させているため、東西も南北も両方斜めになり、東西の軸が右肩下がりになっている。また奥行きがほとんど潰れておらず、地面が「床」ではなく「傾いた長方形の紙」に見える。

次の式に置き換える。yaw 回転は廃止（視点の切り替えも、いったん無しでよい）。

```text
north  = -gy                       // 2D レイアウトで上にあるほど正
height = (level - 1) * LEVEL_H
screenX = cx + gx + north * 0.40
screenY = groundY - north * 0.30 - height
```

狙いは、3つの軸に画面上の固有の向きを割り当てること。

- 東西 = 水平のまま（2D のときの横並びが崩れない）
- 抽象度 = 真上
- 南北 = 右上がりの斜め（北が右上・奥、南が左下・手前）

0.40 / 0.30 / LEVEL_H は設定値にする。LEVEL_H はノードの高さの 2 倍強を目安に。

## 2. 地面を「床」に見せる

- 地面の平行四辺形に、東西方向と南北方向のグリッド線を薄く引く
- 中心ノードの真下を通る東西軸・南北軸だけ、少し太く描く（床の十字）
- N / S / W / E のラベルは、この十字の両端に置く（今は軸と無関係な位置にある）
- 地面は全ノードの影が収まる最小サイズに。今は大きすぎる

## 3. 柱と影を主役にする

- 柱の破線を、背景に対してはっきり見える色と太さにする（今はほぼ見えない）
- 柱に 1 段ごとの短い横線（目盛り）を入れて、何段浮いているか数えられるようにする
- 影は全ノード同じ小さな楕円にする（今はノード幅に比例していて、中心の影が巨大）
- 影は必ず柱の下端に置く
- 最下段（床にいるノート）は柱なし。箱のすぐ下に接地影を描いて「床に置かれている」と分かるようにする

## 4. 脇役を引っ込める（3D モードのときだけ）

- リンクの線を細く・薄くする。今は太い緑線が一番目立ち、柱が負けている
- ゲートの小さな丸とリンク本数の数字は、3D モードでは非表示か極小に
- リンクはゲート間ではなく、ノード中心同士を結ぶ（箱の下に隠れるように先に描く）

## 5. 高さを二重に符号化する

- 抽象度による色分けを 3D モードでも効かせる（今は全ノード同色に見える）
- 箱の肩に小さく「L3」などのレベル表示を付ける

## 6. 要確認（バグかもしれない）

- 「朝のルーティン手順」は L2 のはずだが、柱と影が見えない。子ノードに高さが適用されているか確認してほしい
- 描画順は north の大きい順（奥 → 手前）になっているか

## 合格の目安

- if-then プラン / 中心 / 意志力で続ける が、画面上で水平の一直線に並ぶ
- 全ノードの影が床のグリッドの上に乗り、フレンドの影は東西軸の上、親の影はその右上、子の影は左下に落ちる
- 「行動デザイン」が一番高く、「読書メモ：習慣の本」は北側の床に接している
- 3D をオフにすると、元の 2D とまったく同じ表示に戻る

---

## 6 への回答（エージェント、2026-09-21）

- 高さは `docs/3d-design.md` §3-1 のとおり中心を 0 とした相対値（Up の親 +1、Down の子 −1、それ以外 0）で、床は画面内の最小レベル。fixture では `down::`（朝のルーティン手順）も `example::`（歯磨き後に腕立て、9月20日 朝ランの記録）も Down なので同じ −1 ＝ 床にいる。バグではなく設計どおりで、床のノードには柱を引かない規則になっていた。模式図の「L2」（朝のルーティン手順だけ 1 段浮く）を出すには、`down` と `example` を別の段にする必要がある（§7 の論点）。
- 描画順は投影後の depth 昇順（奥 → 手前）にしている。斜投影では north の大きい順に読み替える（3D-2-1）。

## 追記 2（2026-09-21 夕方、本人）: Up／Down は垂直に、床の平行四辺形は Parents／Children／Left／Right だけ

画面: `docs/images/3d-feedback-two-ups-2026-09-21.png`（Up が 2 つ: `up:: [[行動デザイン]]` と未解決の `up:: [[aaaa]]`）。

- Up のオントロジーが 1 つのときは真上に出てバッチリ。2 つ以上あると 2 つ目の Up が平行四辺形状（床の北の帯）に計算されて出てしまう。
- Down は 1 つでも 2 つでも平行四辺形状に見える。もっと Z 座標のマイナス側、中心の真下に垂直に出てほしい。
- 平行四辺形状に表示するのは Child・Left・Right・Parent。Up／Down は垂直方向と明確に分けたい。

### 原因（エージェント）

1. Up／Down のノードも 2D の北の帯／南の帯の位置（`gy = ∓291`）のまま斜投影しているので、`north` のぶん右上／左下にずれる。1 つのときは列が 1 本で `gx = 0` なのでずれが小さく見えるだけ。
2. `Projection.levelOf` が未解決ページ（ゴースト）を level 0 にする規則（LEV-110）なので、`up:: [[aaaa]]` は Up でも床の帯に置かれる。

### 反映（3D-2、LEV-124）

- 3D では level ≠ 0（Up／Down）のノードを `north = 0`（中心と同じ床の行）に置き、x は中心を挟んで東西に等間隔（1 つなら中心の真上／真下）、高さは level × levelHeight。柱の足元は中心の東西軸上。
- level 0 のノード（Parents／Children／Left／Right／Previous／Next）は今までどおり 2D の帯の位置を斜投影する。
- 未解決ページでも Up／Down のフィールドで結ばれていれば level を付ける（0 に落とすのは兄弟だけ）。
